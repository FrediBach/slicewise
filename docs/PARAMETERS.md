# Slicewise parameter reference

This document describes the user-facing parameters in Slicewise as implemented in `src/App.tsx` and `src/lib/slicer.ts`. Ranges are the limits enforced by the interface. Unless noted otherwise, changing a parameter redraws the preview and affects both SVG and G-code output.

Select controls show a short information banner for the active option. The banner updates after direct selection, randomization, snapshot restoration, and undo or redo.

## Workspace modes

The top workspace switch offers Config, Animation, Sequencer, and the internal **3D** prototype. Sequencer keeps the contour controls editable and turns the latest exact contour result into a deterministic phrase. Quick interaction previews never replace the musical source. If an exact result arrives during playback, its lane grids appear immediately and the sounding phrase changes at the next unscheduled global bar.

The Sequencer transport provides play/pause, return to start, a bar/beat readout, and tempo from **40–240 BPM** (default **110**). Space toggles playback, Home returns to the start, and Left/Right move by one sixteenth-note transport step when focus is not in a form control. Web Audio is created only by the Play gesture and is closed on leaving Sequencer mode.

Lane controls are divided into three workspace tabs. **Pattern** groups the lane type, preset, contour variation, independent clock divider, **1–64** steps, and **0–Steps** Euclidean pulses. **Sound** exposes the selected percussion instrument or the melodic synth's character, waveform, brightness, resonance, sub oscillator, and ADSR envelope. **Shape mapping** groups slice travel, range, geometry warp, and contour influence. The step grid remains visible in every tab so changes can be read against the same cycle preview. Each lane also exposes mute, solo, and deletion. The initial project contains one contour-mapped pluck lane and one synthesized kick lane. Add Melody and Add Drum create independent rows. Changing lane type uses that type's explicit defaults while retaining shared rhythm, timing, probability, expression, mute, solo, direction, and contour-influence settings.

The Sound tab uses an instrument rack with **Oscillator**, **Filter**, and **Amplitude envelope** sections. Drag rotary controls vertically; hold Shift for finer movement. Focus a knob and use arrow keys for one step, Page Up/Down for ten steps, or Home/End for its limits. Click a value to type, then Enter or blur to apply; Escape discards the draft. Envelope times display in milliseconds (attack 1–2,000, decay 10–3,000, release 10–5,000), with logarithmic knob travel for precise short transients. Brightness, sub level, and sustain display percentages; resonance displays Q (0–20). Display rounding does not modify saved values. The ADSR graphic is a schematic with logarithmic time spacing; actual playback follows each note's gate and shape mapping. Drum lanes provide directly selectable instrument pads. The cycle preview sits below the Sound rack.

Pattern uses **Voice**, **Rhythm**, and **Clock & expression** modules. Lane type and clock division are directly selectable buttons; choosing a grid division or a fit-cycle duration replaces the other timing mode. Rhythm faders and −/+ controls adjust integer cycle length and active pulses, with a pulses-per-cycle readout. Reducing cycle length also limits the pulse count to that length.

Shape mapping uses **Contour position**, **Slice travel**, and **Shape modulation** modules. A schematic contour marker shows the normalized contour position; the highlighted slice-window display shows the selected range. Direction buttons choose forward, reverse, or ping-pong travel. Range endpoints stay ordered, including equal endpoints to hold one slice. Percentage faders control position, range, bipolar warp amount, and shape influence. Warp editing is disabled while the source is Uniform. Both tabs support direct numeric entry (Enter/blur to apply, Escape to cancel), native slider keyboard adjustment, and responsive stacked layouts with the cycle preview below the controls. Radio-style option buttons support arrow-key selection without moving the transport.

Each lane receives a persistent color from an eight-color cycling palette. The color connects its header, step hits, traversal trail, and source markers in the main preview. Melodic routes use circular markers; drum routes use diamonds. A lane can be independently collapsed without changing its musical state. Its **Randomize** action affects only the currently visible Pattern, Sound, or Shape mapping tab, preserving the other two groups and the lane color.

Melodic presets are **Contour pluck**, **Body / bass**, and **Fragment / pluck**. Drum presets are **Contour kick**, **Fragment / snare**, and **Rough percussion**. They combine Euclidean density, synth/drum voice, and descriptor mappings into useful starting points: body/length drives bass, path fragmentation drives pluck or snare, and roughness drives synthesized hat percussion. Applying a preset retains lane identity and transport state.

Melodic sound design supports sine, triangle, sawtooth, and square/pulse waveforms; **0–100%** brightness, **0–20** filter resonance, **0–100%** sub oscillator, **0.001–2 s** attack, **0.01–3 s** decay, **0–100%** sustain, and **0.01–5 s** release. The sample-free, 808/909-inspired drum set contains kick, snare, clap, rimshot, closed/open hi-hats, low/mid/high toms, low/mid/high congas, cowbell, crash, and ride. Hat voices automatically share a choke group, and every instrument uses its conventional General MIDI percussion note for export.

The per-lane Variation control offers **No variation**, **Accent**, **Octave** (melodic lanes), **Articulation**, and **Ratchet**. A target uses its own contour-mapped, stateless probability condition rather than reusing the lane's trigger probability. Accent raises velocity, Octave transposes by an octave, Articulation shortens the note or drum decay, and Ratchet emits two to four evenly spaced repetitions. A small amber marker identifies expression in the deterministic cycle preview. Repeat/evolve behavior, playback, seeking, and MIDI export all resolve from the same project seed, lane, cycle, step, and target coordinates.

Sequencer edits autosave the versioned musical project to browser-local storage; source meshes, artwork, and contour descriptors are not stored. Older projects migrate with their contour presets intact, expression disabled where it was previously unavailable, and distinct default contour routes. MIDI export requires the current exact shape and an explicit duration of **1, 2, 4, 8, 16, or 32 bars** (default **4**). The format-1 file contains a tempo/time-signature conductor track, one track per lane, melodic program assignments, and General MIDI channel-10 percussion. Muting, soloing, rational lane timing, swing, seeded trigger probability, and seeded expression use the same event compiler as live playback.

3D displays one current Config mesh after the shared Object transformations. Drawing-only controls stay mounted but hidden; their values are retained. Entering from Animation restores its frozen Config settings, and leaving Sequencer stops audio. Line-art sources show an unsupported-source message; open mesh surfaces may be inspected without being declared solids.

The viewport toggle explicitly says **Show slices** or **Hide slices**. Changing the field, levels or slice selection shows the new contours automatically; print placement and camera navigation retain the visibility choice. Source comparison applies only to the currently prepared artifact and resets for a new result. Slice extraction failures are also shown in the viewport status.

3D buttons are compact 26 px controls, including viewport and preparation actions. Construction permits 64 tool loops, 32,000 path vertices and a conservative cumulative estimate of 8,000,000 capsule-construction triangles. Aggregate source/tool and output meshes allow 500,000 triangles; intersection auditing allows 20,000,000 work units. The source slice extractor remains limited to 250,000 triangles. Budget errors show complete selected workload counts and the limits exceeded. Complex shapes may be rejected; reducing selected slices or explicitly allowing path approximation can help, but source inputs are not repaired. Generated tools and placed buffers use exact-coordinate cleanup. Boolean results use the selected Result vertex cleanup tolerance (0.00001 mm by default, or zero for exact-only). Fixed representative vertices prevent chained merges from exceeding that tolerance. Strictly zero-area faces and unused vertices are then removed. The Generated mesh cleanup disclosure lists changes, the stage tolerance and maximum measured vertex movement, including for rejected preparations. Every cleaned result must pass full geometry auditing.

Preparation states distinguish source preview, pending, accepted experimental result, rejection and cancellation. Pending native work keeps the untreated source visible. Settings/source changes terminate obsolete preparation and clear old geometry; repeated identical blur/resize requests retain the current result. Rejected or incomplete audits never expose a current accepted solid. Geometry diagnostics include completed/failed/not-run checks and bounded issue counts; separate manufacturing advisories use the configured build volume, 0.05 mm bed band and 45° overhang-from-vertical assumption. Global wall thickness, support and stability remain unchecked. 3MF and binary STL export are available for the current untreated source once its physical size is confirmed, or for a current accepted single-body treatment result whose eight geometry checks passed. The panel and main Export action download the exact worker-serialized artifact in millimeter coordinates. Changing settings/source, cancellation, rejection or mode exit clears both files. Manufacturing advisories remain visible; this is experimental geometry interchange, not a print-readiness certification. Untreated exports include Object transforms, sizing and print placement, without treatment or geometry audits; slice-field errors do not block source export. Treated results still require a single audited body.

Imported meshes are welded, centred on their bounding-box midpoint, and uniformly normalized to a bounding-sphere radius of 1. Original model units therefore do not determine output size; artboard, margin, scale, and offsets do.

Built-in demo meshes include Torus knot, Ripple sphere, Rounded cube, Rounded pyramid, Twin balls, Pebble, Rounded cylinder, Soft diamond, Ring torus, Twisted bloom, Hourglass, Tetrapod, and Radish. Rounded pyramid softens the square base, edges, and apex; Twin balls joins two lobes through a smooth waist; Pebble is a flattened ellipsoid; Rounded cylinder has soft shoulders and ends. They are deterministic, closed procedural meshes and initially use Z-up orientation.

## Object

**Object** reshapes triangle-mesh sources before contour construction. **Enable object transformations** (`objectEnabled`, default off) enables the stage. Uploaded meshes, built-in demos, generative meshes, terrain, and extruded SVGs are supported. Direct SVG centrelines and hyperbolic tilings bypass it and disable its controls while retaining the settings.

The fixed order is **object rotation → stretch → taper → bulge/pinch → shear → twist → bend → ripple → organic displacement**. Each transformation has an independent enable checkbox (`objectStretch`, `objectTaper`, `objectBulge`, `objectShear`, `objectTwist`, `objectBend`, `objectRotation`, `objectRipple`, `objectNoise`, all initially checked). Disabling a transformation preserves its values. All initial numeric values are neutral, so enabling the stage alone leaves the drawing unchanged.

Axes remain fixed in the normalized coordinate frame after **Model up axis** correction. Object rotation turns the source inside that frame, so rotating a long model changes how the X/Y/Z reshapers act on it. Saved configurations combining rotation with other transformations will produce a different shape than the former rotation-last order. Taper, bulge/pinch, shear, twist, bend, and ripple measure their lengthwise extent at the start of their respective stages. There is no automatic recentring or renormalization after deformation. Existing View scale and offsets control the final framing; large stretches can extend beyond the artboard. Cutting planes, SVG cutting paths, and wavefront origins retain their existing coordinate frame. View depth slicing continues to follow the camera.

Bulge/pinch uses a compact smooth profile: inside the band, radial scale is `1 + (amount / 100) × (1 − q²)²`, where `q` is distance from the centre divided by half the width. Outside the band the surface is unchanged; displacement and slope both approach zero at its edges. Bands centred near an endpoint can extend beyond the model. Shear preserves volume and connectivity and does not subdivide the mesh by itself. Changing centre, width, or direction while the corresponding amount is zero is neutral.

Ripple applies a sine-wave translation to each cross-section. Organic displacement samples three independent channels of smooth seeded 3D value noise at each vertex, after ripple. It is a spatial distortion, not displacement along normals: coincident vertices receive identical offsets, including imported seams. Its noise lattice is anchored at the origin. A flat extent along the ripple axis produces no wave. Changing wavelength, phase, direction, feature size, or seed while the corresponding amount is zero leaves the mesh unchanged.

All mesh-dependent calculations use the resulting surface, including hidden lines, silhouettes, slice rays, Contour Weave, geodesic graph distances, and curvature. Terrain roads and rivers require the original height-field geometry and are temporarily unavailable whenever a non-neutral object transformation is active. Their saved values are retained. Strong bends can fold or self-intersect a wide object; this stage does not perform collision repair or solid booleans.

Nonlinear transformations refine coarse source triangles using shared edge midpoints before moving vertices. Refinement preserves the authored triangle surface and boundaries, uses the same mesh for quick and exact renders, and is independent of Curve quality. It normally targets edges no longer than 1/16 in source bounding-box-normalized coordinates. An active bulge narrower than 50% uses finer refinement: 1/32 for widths 25–50% (excluding 50%), and 1/64 below 25%. Active ripple wavelength and organic feature size below 50% also select 1/32; the finest requirement wins. These density steps target at least eight samples across a feature in source space; extreme combinations of earlier deformations can compress detail further. Refinement is cached independently of amounts, centre, direction, phase, and seed. Up to eight refinement passes and a triangle budget bound work; the budget is 250,000 triangles or the original triangle count when already larger. If required refinement exceeds the budget, rendering reports an actionable error; simplify the source, widen the bulge, or increase ripple wavelength or organic feature size. Fine source geometry remains important for detailed curvature and surface-graph distances.

**Reset object** restores defaults and clears object numeric targets in both Morph dimensions. It is undoable and retains randomization locks. The master toggle, individual toggles, axes, and numeric values participate in undo/redo and named snapshots. Numeric values also support X/Y morphs and animation. Organic seed is rounded per morph instance and held between animation keyframes, changing at the next keyframe; enable toggles and axes are fixed from the animation's Config base. Randomization uses restrained numeric ranges (stretch, bulge width, ripple wavelength, and organic feature size 70–140%; bulge centre 25–75%; ripple amount ±10%; organic amount 0–10%; seed 0–9999; other numeric values within ±60) and respects individual locks and section scope.

## Animation

The workspace mode switch changes between static configuration and timeline animation. Entering Animation mode freezes the current render settings, disables non-morphable controls, suppresses the overlaid X/Y Morph feature for animation frames, and creates a protected keyframe at time zero. Returning to Config mode restores the frozen settings without applying keyframe edits to them.

Keyframe diamonds can be selected or dragged along the timeline; occupied times are rejected and the time-zero keyframe cannot move. Space toggles playback, arrows step one frame, Shift + arrows step ten frames, K adds a keyframe, Delete/Backspace removes the selection, Home/End jump to the timeline boundaries, and Ctrl/⌘ Z handles animation-scoped undo while Animation mode is active.

Playback automatically caches completed preview frames and prepares upcoming frames when the worker is free, improving repeat playback. Complex models show completed frames as they become available. The cache is limited to 240 frames and approximately 32 MiB; larger animations use more widely spaced preview samples to stay within those limits. Edits and source changes invalidate cached frames, and leaving Animation mode releases them. Pause and video export always render at full quality.

Numeric parameters interpolate linearly. Integer counts round after interpolation. Ink colour interpolates per RGB channel. Seed parameters hold their earlier value until the next keyframe so seeded geometry does not reshuffle continuously. Video export is available when the browser exposes WebCodecs VP9 or VP8 encoding; unsupported browsers retain timeline editing and playback. Export runs sequentially, remains local to the browser, and can be cancelled.

The current animation project autosaves locally after timeline edits. Slicewise associates it with a generated browser-local workspace ID rather than a source filename, migrates stored version-one data on load, and restores it when its frozen base settings match the current Config snapshot. Animation data stays separate from ordinary named parameter snapshots, and uploaded source mesh or artwork bytes are not stored with it. See `docs/ANIMATION.md` for the persistence, interpolation, and export contracts.

Canvas gestures provide equivalent controls: drag to change azimuth/elevation, Shift-drag to roll, Space-drag to offset, and use the mouse wheel to scale. Double-click resets Scale and both offsets, but leaves orientation unchanged.

For a classic isometric view, set Perspective to 0%, Lens distortion to 0%, Azimuth to 45°, Elevation to 35.3°, and Roll to 0°. Other orthographic azimuth/elevation combinations produce dimetric, trimetric, plan, and elevation views.

All listed modes are projection warps of the rendered Euclidean mesh, not replacements for its intrinsic geometry or contour metric. The fixed order is camera basis, orthographic/perspective blend, the selected projection warp, optical lens distortion, then sheet scale and offset. None is the ordinary orthographic/perspective camera result and therefore doubles as the orthographic choice when Perspective is 0%.

For spherical modes, normalized camera-plane radius `r` lifts through the sphere's exponential map at angular distance `ρ = πr/2`; `r = 1` is the spherical horizon. Stereographic uses `(X/(1+Z), Y/(1+Z))`, gnomonic uses `(X/Z, Y/Z)` on the front hemisphere, and the horizon-normalized Lambert equal-area model uses `(X/√(1+Z), Y/√(1+Z))`. Camera azimuth, elevation, and roll already orient this construction, so there is no redundant spherical orientation control. Stereographic and Lambert split at their antipodal singularity; gnomonic splits at the horizon. Extremely large singular samples are rejected before sheet scaling.

At the Klein ↔ Poincaré 100% endpoint the disk-model relation is `p = k / (1 + sqrt(1 − k²))`. Möbius uses `z′ = exp(iθ) · (z − a) / (1 − conjugate(a) · z)` with a bounded translation parameter `a`. Circle inversion uses `c + R²(p−c)/|p−c|²`. Nonlinear spans are adaptively subdivided according to Curve quality before visibility and output processing, so preview, SVG, and G-code follow the warped curve rather than connecting distant transformed endpoints with straight chords. Hidden-line depth faces are also subdivided for spherical and inversion modes near nonlinear domains.

### Slice field

**SVG paths** uses the SVG's actual subpaths as cutting surfaces through a triangle mesh. Upload artwork with **SVG cutting paths** (`svgSliceFile`), independently of the source model. Open strokes remain open; closed outlines and compound-path holes retain their own paths. Text must be converted to paths. Fill colours and stroke widths do not affect the cuts; SVG clipping/masks and embedded images are not cutting geometry. Curves are sampled into polylines (48 divisions per curve).

**Logo scale** (`svgSliceScale`) defaults to 100%, range 1–300%; at 100% the longest artwork dimension spans the normalized model diameter. **Logo X/Y** (`svgSliceX/Y`) default to 0, range −200–200% of model radius, in the cutting plane. **Logo rotation** (`svgSliceRotation`) defaults to 0°, range −180–180°. Existing **Azimuth/Elevation** orient the cutting direction; the default 0°/90° puts the logo in model XY and extends it along Z. **Divergence** stays available: 0° extends paths straight; higher values widen the logo with depth from the minimum model coordinate along that direction. The scale factor is `1 + tan(divergence / 2) × depth` in normalized model units, about the logo's placement centre.

Line count, gap easing, slice LFO, continuous spiral, and slice explosion do not apply to SVG cutting paths. Contour Weave takes precedence while enabled. This mode requires a triangle mesh; line-art sources retain their existing projection workflow. Camera, visibility, colours, and downstream effects apply normally. Quick previews preserve all cutting paths. Each subpath is a sequencer slice. Parsed cutting paths and placement are included in local parameter snapshots and undo/redo; the original SVG file is not retained. Imports are limited to 2 MB and 20,000 sampled points; rendering checks triangle bounds first, then limits intersecting candidates to 20 million pairs and emitted segments to 300,000 with an instruction to simplify. The styled SVG drop area supports browsing, keyboard activation, and drag-and-drop without replacing the source mesh. Read/parse failures stay visible below it; selecting SVG mode before uploading is an empty state. Faces exactly coplanar with a cutting surface are omitted because their intersection is an area rather than a unique line.

**Roads and Rivers require Generative terrain in Z-up orientation.** Their controls are disabled for other sources, which emit no routes even if an older snapshot requests them. Routes are solved against the actual mesh before projection, so they follow the same camera transforms and hidden-line filtering as the terrain. Rivers strictly descend; roads prefer gentler ground within a hard grade limit. Corner rounding is draped back onto the terrain and rejected when it would violate those constraints. These are bounded routing approximations, not civil-engineering or full hydrological simulations. Steep terrain, short drainage paths, and disconnected traversable regions can yield fewer routes than requested. Lower Vertical relief can make more of the landscape traversable.

The former decorative Lakes option has been removed; older snapshot values are discarded. Believable lakes would require basin filling and water levels rather than arbitrary shoreline shapes. Other map symbols remain illustrative 2D cartography inside the convex footprint of finished linework, clipped by the existing mask/artboard pipeline. The same single-stroke vector features, A–Z lettering, and physical contour clearances are used for SVG and G-code. Crowded labels are omitted rather than overlapped. Increasing a family's count preserves its earlier accepted candidates while the footprint and preceding feature families are unchanged.

Contour Weave requires a triangle mesh. It is disabled for SVG centrelines and hyperbolic tilings; extruded SVGs are supported. It replaces the ordinary slice field, spacing easing, divergence, slice LFO, spiral, and slice explosion while enabled. Their settings are retained for when weaving is turned off. Line count (bounded to 2–400 inside the weave kernel), camera/projection controls, hidden-line removal, silhouettes, colours, and downstream effects remain available. Numeric weave controls and Weft ink support X/Y morphs and animation. Obsolete duplicate rotation/scale/offset/interval settings and their morph targets are discarded when restoring snapshots.

The two material-coordinate fields are sampled at mesh vertices. Thread iso-lines, ribbon sides, and crossing gaps are interpolated inside individual source triangles, then chained in 3D before projection. Both families use the same visibility test. There is no displaced or duplicated object, and no screen-space crossing detection. This is a procedural surface fabric, not a cloth-physics simulation or a distortion-free UV unwrap: spacing changes on steep surfaces, and coordinate directions tangent to flat faces can produce sparse regions. Adjust Fabric azimuth, tilt, or roll to change that alignment; finer source meshes resolve strong twist more accurately.

Widths and clearances use a reference scale of half the shorter margin-adjusted sheet dimension per normalized model unit. Camera orbit and zoom therefore never change which material crossings exist; widths are foreshortened with the surface. Gap protection may retain touching ink in tight regions. Keep Remove hidden lines on for opaque woven objects; turning it off deliberately reveals back-surface threads. Preview retains the full material grid to avoid changing weave topology during orbit, while reducing projected curve precision. A worker-local cache retains up to four geometry variants per mesh. Requests stop with an actionable error above two million triangle/level candidates or 300,000 emitted segment attempts. Geometry uses the same finished centreline segments for SVG and G-code, with deliberate gaps protected from travel optimization.

Effects use a fixed composition order: ordinary contour generation and slice explosion, or surface-weave generation; then Humanizer geometry, yarn cutting and curling, Block glitch cutting and displacement, Scan-band glitch tearing, Staggered slices, Wraparound tear, Tile shuffle, Sample-and-hold, kaleidoscope mirroring, artboard and generative-mask clipping, vector zoom destination clearing/cropping/scaling, gradient and line-weight styling, halftone dashes, chromatic copies, topographic annotations, vector zoom guides, Misregistration copies with a second artboard/mask clip, then the technical blueprint overlay. All effect toggles can be enabled together. Randomization samples them independently while preserving individual locks.

G-code uses millimetres, absolute positioning, and feed-per-minute mode (`G21`, `G90`, `G94`). Separate colour groups pause with `M0` for a pen change. When G-code is selected, **Machine preflight** independently parses the serialized file before it can be copied or downloaded. It rejects unsupported commands, malformed or non-finite values, incomplete setup, incorrect feeds or pen heights, pen-down rapid travel, out-of-sheet compensated carriage motion, a final machine layout larger than the selected working envelope, invalid expressive setup, pressure outside the configured Z range, unsafe pen changes, and unsafe shutdown. Rotated files also include a G-code layout comment. This software check cannot detect physical registration, real contact pressure, holder geometry, belt tension, or paper flatness; run calibration and a pen-free dry run, confirm placement in Universal Gcode Sender, and frame the sheet with the pen raised before plotting.

**Direct connection · GRBL** uses the Web Serial API to connect at 115200 baud and send the same preflight-validated G-code directly to the selected plotter. Slicewise strips comments for the controller and sends one command at a time, advancing only after GRBL replies `ok`; controller `error:` and `ALARM:` responses stop the stream with the source line and command. Sending requires a separate motion confirmation. Expressive confirmation additionally identifies the required physical angle and resolved machine direction, emitted Z range, compensation state, and calibration requirement. At each `M0` pen-change pause, it waits for the operator to change the pen and explicitly confirm before sending GRBL cycle start (`~`). **Stop** immediately requests GRBL feed hold (`!`) and cancels further commands; because feed hold freezes the current machine state, the pen may remain down. Web Serial currently requires a supporting desktop browser such as Chrome or Edge and a secure context (HTTPS or localhost). Port permission, model data, and G-code remain local to the browser.

## Randomization, locking, and history

- **Randomize parameters** changes creative view, contour, colour, and effect settings within curated subranges. It deliberately keeps the loaded source and physical sheet dimensions stable. Its ranges can be narrower than the manual control ranges.
- The dice button in a group header applies the same curated randomization only to that group's parameters. Parameters in other groups remain unchanged.
- An open-lock button means the parameter participates in randomization. Clicking it shows a closed lock and excludes the base value—and any active morph target for that parameter—from later randomization.
- **Lock all** and **Unlock all** temporarily set every randomization lock at once. Click the active bulk button again to restore the previous individual lock set. Changing an individual lock ends that temporary bulk state; the next bulk action starts from the newly edited set.
- Randomization locks are available for morphable numeric/colour controls (including wavefront centres, cylinder orientation, both geodesic seed directions, curvature smoothing/range/contrast, focal length, perspective, every projection strength/centre/radius, Klein↔Poincaré warp, lens distortion, Block, Scan-band, Staggered-slice, Wraparound-tear, Tile-shuffle, Sample-and-hold, and Misregistration geometry/colours where applicable, Kaleidoscope controls, and all vector zoom positions/dimensions/margins/guide colours), Projection warp, Geodesic mode, Curvature field, Include zero curvature, Divergence, Background colour, Gap easing, Slice field, slice-plane modulation, Line-weight variation, Continuous spiral, Remove hidden lines, Add outer silhouette, Use colour gradient, Block glitch and its direction/destination clearing, Scan-band glitch and its orientation, Staggered slices and its orientation/pattern, Wraparound tear and its orientation, Tile shuffle, Sample-and-hold and its axis, Misregistration and its copy scope, Kaleidoscope, every Vector zoom slot/shape/corner, Halftone stroke, Chromatic aberration, Humanizer, Technical blueprint, and Topographic map.
- **Undo** and **Redo** keep up to 100 snapshots of render parameters. Source selection, SVG extrusion, model up axis, paper preset as a label, export format/profile, and G-code-only values are not part of those snapshots.
- **Named snapshots** save the current render parameters, X/Y morph configuration, and randomization locks in the browser's IndexedDB storage. Each entry keeps its name and creation date and can be restored or deleted later. Like undo/redo, named snapshots do not replace the loaded source or export-machine settings.

### Weather-map bands

**Weather-map bands** (`weatherBands`, default off), under Effects → Post-processing, applies an eleven-colour palette by contour order, blended from **Low colour** (`weatherLowColor`, default `#276419`) through **Midpoint colour** (`weatherMidColor`, default `#ffffff`) to **High colour** (`weatherHighColor`, default `#8e0152`), overriding gradient and indexed contour colours while active. Intact closed loops receive opaque SVG fills, drawn largest first so smaller nested loops form discrete bands. Open, clipped-open, and degenerate runs stay unfilled. The colours are decorative contour positions, not measured pressure anomalies. Use closed contours, a white background, and disable hidden-line removal for the clearest filled result. Perspective overlaps are layered by projected loop area rather than surface depth.

SVG preview and export include the fills; G-code retains the coloured contour outlines as pen groups without generating solid-fill hatching. Silhouettes and annotations keep their existing colours. The toggle and all three colours participate in undo/redo and saved render settings. Colour pickers and six-digit hex inputs are available while the effect is enabled; colours apply to both SVG fills/strokes and plotter pen groups.

### Slice rays

**Contours → Slice rays** adds optional outward strokes where mesh slices meet the model. **Enable slice rays** (`sliceRays`) defaults to off. Rays use the local slice or surface direction, follow camera projection and slice explosion, inherit contour colour/weight, and share downstream effects, mask/artboard clipping, SVG export, and G-code output.

| Control          | ID                  | Default | Range  | Meaning                                                                                                                                       |
| ---------------- | ------------------- | ------- | ------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| Ray amount       | `sliceRayAmount`    | 24      | 0–200  | Rays per slice, distributed across eligible runs by arc length.                                                                               |
| Ray length       | `sliceRayLength`    | 12%     | 0–100% | Maximum length relative to the normalized model diameter, before variation and collision shortening.                                          |
| Length variation | `sliceRayVariation` | 35%     | 0–100% | Deterministically shortens individual rays by up to this percentage. Zero gives equal lengths unless a ray meets another boundary.            |
| Ray fade         | `sliceRayFade`      | 50%     | 0–100% | Fraction of each ray's reach occupied by increasingly short dashes and widening gaps. Zero gives a solid ray; 100% begins fading at its root. |

For planar and divergent slices, rays lie in each individual slice plane, point into empty space (including holes), and stop before crossing another closed contour in that plane. Open planar contours are skipped because they do not define an inside.

For **Spherical wavefront**, rays travel in straight lines **away from Origin X/Y/Z**. For **Cylindrical wavefront**, they travel radially away from the positioned cylinder axis. A surface point emits a ray only when that direction points out of the mesh; entry points and tangencies emit none. Moving a spherical origin outside a convex object therefore leaves rays on the exit side, away from the source. An origin inside the object produces rays around it. Only the exterior extensions are drawn, not the lines inside the object. Ray amount sets the number of candidate locations per slice; exit filtering can reduce the emitted count.

For modulated slicing fields, straight rays leave along the local tangent of the cutting surface, oriented outward using the mesh normal. For geodesic and curvature fields, which have no cutting surface outside the mesh, rays leave along the outward surface normal perpendicular to the contour. These modes also accept open contours. Normals use source vertex normals, or triangle winding for authored faces and meshes without normals. Closed meshes with reversed winding are corrected for the exit test; open surfaces retain their authored normal direction. Singular or ambiguous directions emit no ray. These are local straight-ray effects: they do not bend along curved cutting surfaces or perform mesh collision tracing; hidden-line removal hides occluded portions. All fade dashes share their root's explosion offset. A zero amount or length emits no rays. Very complex sections reduce ray count to bound intersection work. Fading uses physical gaps rather than opacity, and plotter path optimization preserves those gaps.

Available for Height, View depth, Model width, Model depth, Custom plane angle, Spherical wavefront, Cylindrical wavefront, all Geodesic modes, and Mesh curvature on mesh sources. Divergence and slice-plane modulation are supported. Continuous spiral, Contour Weave, SVG cutting paths, and line-art sources disable the controls and bypass generation without discarding the saved ray settings. The toggle and numeric values participate in undo/redo, named snapshots, randomization/locks, and worker render snapshots; numeric values also support morphs and animation. Ray decoration does not affect sequencer contour measurements.

In Print view, **Fit build volume** frames the entire configured printer volume without changing object geometry or print placement. **Fit** continues to frame the object. Switching projection retains the most recent fitting target. Out-of-volume notices list the excess in millimeters at each boundary (X−/X+, Y−/Y+, Z−/Z+); Z− means below the bed.

**Export STL (mm)** writes one binary STL with a `-3d-mm.stl` filename. Import as millimeters: STL has no standard unit metadata. Camera and source-comparison controls do not change the exported mesh. With no prepared result, export uses the current untreated source. 3MF embeds explicit millimeter units and a named object in a standard Core model package.

**Export 3MF** downloads `-3d-mm.model.3mf` with the exact indexed placed mesh, one named object and an identity build item. The main Export action prefers 3MF when available; the surface panel offers both formats. The package contains geometry and units, without printer profiles, supports or slicing toolpaths. 3MF XML is bounded to 96 MiB; packaging failures are reported separately and leave an already prepared STL available.

## Portable presets

The **Presets & snapshots** collapsible is available in Config, Animation, Sequencer, and 3D. Its **Presets** tab manages full workspace files; its **Snapshots** tab manages drawing parameters, morph targets, and randomization locks stored in this browser. Each tab explains its scope and storage. Switching tabs preserves file sessions and unfinished names; drawing snapshots remain unavailable in 3D and locked during Animation. A `.slicewise-preset.json` file saves all authored domains, including disabled effects, inactive mode projects, the independent Animation base, randomization locks, export and machine settings, paper orientation, and 3D dimensions and presentation. Playback, device connections, generated output, validation results, and 3D size confirmation are transient.

Enter a name, description, and comma-separated tags, then **Save preset** or **Save as copy**. **Include source files** defaults on and embeds the original STL, OBJ, PLY, or SVG bytes; built-in and generated sources use recipes. Turning it off produces source references verified by hash: **Locate** each requested source before loading. No local path is stored. The maximum source size is 32 MiB, total decoded assets 64 MiB, and JSON file 96 MiB. A successful save reports its file size; failed or cancelled saves retain unsaved changes. An externally changed file must be reloaded or saved as a copy.

**Open file** replaces the full workspace after validation and source preparation. **Cancel loading** stops preparation; **Undo preset load** restores one previous full workspace. Ordinary parameter undo starts afresh after a preset load. Loading is unavailable during a machine send or video export. Imported 3D dimensions are preserved, but source size must be confirmed again before export. Local machine-plane calibration libraries stay separate.

Choose a preset folder to browse recursively, search names and tags, filter by mode, or sort by name and modification metadata. **Import files**, **Duplicate**, **Rename**, and **Delete** manage local files. Rename verifies a new copy before deleting the original; deletion asks for confirmation. The folder is remembered when the browser supports handle storage; **Refresh / reconnect** restores access when permission expires. Local file operations require File System Access support. **Examples** remain usable without that API; **Save local copy** creates a new preset and retains attribution.

Existing named parameter snapshots remain available. To turn one into a complete preset, restore it into the desired current workspace, then save a preset; source and mode settings come from that workspace, not from the older snapshot.
