# Slicewise architecture

This document describes the maintained Vite/React application under `src`. The root-level `slicewise.html` is a historical prototype and is not part of the production module graph.

## Design goals

Slicewise is organized around four constraints:

1. Model data stays local to the browser.
2. Expensive geometry work runs away from the main UI thread.
3. The contour engine remains independent of React and the DOM.
4. Existing control element IDs form a stable adapter between React markup and the imperative browser runtime.

The fourth constraint is intentional. React owns the interface structure and stateful controls; `lib/slicer.ts` owns the high-frequency drawing state and binds to controls by ID. Refactors must preserve those IDs unless the runtime binding is updated at the same time.

## Runtime data flow

```text
React panels and controls
        │ DOM events / stable element IDs
        ▼
lib/slicer.ts ────────────────┐
        │                     │
        │ mesh source         │ settings snapshot
        ▼                     ▼
mesh.ts / demo-meshes/  slicer-worker.ts
                              │
                              ▼
                      contour-engine.ts
                              │
                       SVG + toolpaths
                              │
                              ▼
lib/slicer.ts ── preview / clipboard / download
                              │
                              └── gcode.ts for G-code export
```

Generative meshes and terrain use a separate path: `slicer.ts` sends source-discriminated parameters to `generative-mesh-worker.ts`, which calls `generativeMesh.ts` for implicit solids or `generative-terrain.ts` for square height fields and transfers typed-array buffers back to the main thread. Uploaded SVG artwork is parsed lazily through `svg-mesh.ts`. It can become an extruded mesh or scale-axis centreline polylines; centreline points and run offsets are transferred to the contour worker as typed arrays.

## Module responsibilities

### React layer

- `main.tsx` mounts the application and loads global styles.
- `App.tsx` is the composition root. It bootstraps the browser runtime and arranges panels, actions, and the preview workspace.
- `components/panels/*` groups markup by product feature. Panels should remain declarative and retain the DOM IDs consumed by the runtime.
- Complex panel subsections live in feature-named subdirectories such as `components/panels/contours/`. These components may reorganize declarative markup, but the runtime-facing control IDs, hidden wrapper IDs, defaults, and custom-event contracts remain stable.
- `components/panels/OutputPanel.tsx` is a compatibility barrel for the independently owned appearance, canvas, effects, vector-zoom, and export components under `components/panels/output/`. Callers should keep using the barrel unless they need one focused component in isolation.
- Top-level parameter groups use native `details` accordions through `components/ui/section.tsx`. Their controls remain mounted when collapsed so `lib/slicer.ts` can keep binding to stable IDs. The Export section is the deliberate performance exception: while it is collapsed, background G-code serialization, validation, and path-preview updates are suspended; reopening it refreshes the preflight from the latest exact render.
- `components/controls/FormControls.tsx` contains shared numeric, colour, checkbox, morph, and randomization controls.
- `components/controls/GradientChooser.tsx` owns editable gradient-stop state.
- `components/ui/*` contains small, style-oriented primitives without domain behavior.
- `components/sequencer/SequencerWorkspace.tsx` publishes `sequencermappingvisibilitychange` while its Shape mapping tab is open and `sequencerpreviewchange` while a step is hovered or focused. `lib/slicer.ts` uses the former to draw complete, bounded-density lane routes with start/end, direction, and contour-position cues over the transformed preview SVG, then layers the current step segments above those routes on every transport update. A step inspection temporarily replaces the playhead highlights with the exact geometry-warped source slices for the inspected step; outside mapping, transport updates use the same overlay for current steps. Persistent lane colors link rows to their trails, while circular melodic markers and diamond drum markers keep roles distinguishable without relying on color alone. Exact sequence features retain a compact arc-length sampling of each projected slice so lanes can follow distinct routes instead of sharing the slice centroid.

### Geometry and export layer

- `mesh.ts` parses supported mesh formats, welds and normalizes geometry, and calculates vertex normals.
- `solid-kernel.ts` is the internal Phase-0 3D feasibility adapter. It accepts explicit Z-up millimeter buffers, isolates Manifold import/union/difference and measurements, limits input/output complexity, and releases owned WASM solids in success and failure paths. Rounded trial tools are convex hulls of identical endpoint spheres, unioned in batches; unexpected boundary shells fail both before and after buffer conversion. Sources, active tools and exact Float32 outputs also pass independent topology audits; reports retain input warnings. Kernel acceptance is not full print validation. `three-d-feasibility.ts` supplies analytic baseline tools and actual contour sweeps on sphere/box/torus/sheared/twisted/bent fixtures. `three-d-feasibility-worker.ts` loads the pinned WASM asset locally for the separate `tools/three-d-feasibility.html` developer page. The drawing pipeline does not import these kernel/trial modules; explicit preparation in the 3D worker now uses the kernel adapter, while the separate trial remains independent. See [the feasibility record](./THREE_D_FEASIBILITY.md) for commands, evidence, and open gates.
- `planar-sweep.ts` builds experimental indexed circular tubes from closed planar paths using capped miter joins. It reports corner extension and straight-profile deviation and audits the exact Float32 output before returning a tool. The CLI `scale-sweep` trial uses these tools instead of capsule unions; this is a separate join geometry, not the production surface-normal profile implementation.
- `contour-approximation.ts` provides explicit, bounded closed-path approximation with retained source vertex indices and measured path deviation. `slice-treatment.ts` can opt into it using a separate path tolerance, retaining summary measurements on recipes and budget errors. Source geometry and exact extracted contours are untouched; path-distance bounds do not establish equivalent tool topology or treatment depth.
- `slice-geometry.ts` owns the unchanged run-chaining routine shared with `contour-engine.ts`, plus a separate strict planar extractor for the manufacturing trial. The latter retains source revision, ordered field levels, triangle/barycentric ownership, geometric normals, disconnected runs and closure flags in typed arrays. Edge/vertex identity prevents accidental joining of nearby surfaces; ambiguous coplanar/branching cuts and budgets fail explicitly. Drawing field evaluation, normal-guided smoothing and cached slice construction remain in `contour-engine.ts`.
- `print-validation.ts` audits exact indexed artifacts without repair: finite buffers, indexed face degeneracy/duplication, oriented edge incidence, single-cycle vertex links and signed shell volumes. It then runs `print-intersections.ts` on topology-checked buffers. After surface checks pass, `print-shells.ts` classifies shell nesting and orientation. Reports bound diagnostic samples; the full manufacturing check remains unperformed. `print-manufacturing.ts` provides a separate initial advisory screen. Invalid artifacts throw structured errors at the kernel boundary; topology-checked artifacts are not declared print-ready.
- `print-intersections.ts` checks triangle surface contacts with unordered region-pair traversal of a deterministic median bounding-volume hierarchy and conservative separating-axis tests, including coplanar pairs. Adjacent pairs use shared-edge side tests and shared-vertex direction-cone tests to allow their common boundary while rejecting additional overlap. It reports numerical tolerance, separate adjacent/non-adjacent pair counts and bounded samples, and rejects exhausted traversal budgets with incomplete counts. No geometry or drawing cache is changed. These floating-point checks are conservative at the reported tolerance; shell nesting is a separate stage and manufacturing validity remains untested.
- `print-shells.ts` groups the audited connected boundaries, computes bounded solid-angle winding queries between shells and validates an alternating orientation forest. Shell records retain original component/sample IDs, parent, depth and signed volume. Physical body count is available only when all containment/orientation checks finish successfully; cavities do not count as bodies, while solid islands inside cavities do. Bounds only reject impossible containment candidates, never prove containment. No geometry repair or winding correction is performed.
- `print-manufacturing.ts` screens the current artifact against explicit Z-up build bounds, bed tolerance and a downward-overhang threshold. It reruns geometry validation to avoid stale reports, then visits every triangle for bounds, clipped near-bed projected area and overhang area/face samples. Invalid geometry makes measurements unavailable. Optional thickness sampling runs through `print-thickness.ts`. Advisories preserve geometry and cannot establish global minimum thickness, stability, adhesion or print readiness. The developer trial records the assumptions, diagnostics and separate screening time for each accepted result. Per-body bed-band contact uses validated exterior shells and fresh component labels; cavity walls are excluded and nested material islands remain separate bodies. Zero-contact bodies produce an advisory even when aggregate contact is positive; this does not establish support or stability.
- `print-thickness.ts` estimates inward-normal chords from fixed interior barycentric samples on already audited output faces. It reserves requested priority face IDs, fills remaining samples deterministically by triangle index and stops each ray at the first boundary. Ambiguous, near-origin, missing or budget-truncated exits remain unresolved. Reports retain sample locations, face IDs, measured minima, threshold counts, work and the area fraction of faces with a resolved sample; that fraction is not proven surface coverage. All work is DOM-free and bounded.
- `slice-treatment.ts` owns pure All/range/every-N level selection and serializable circular capsule recipes in millimeters. It preserves every run at a selected level, rejects open runs and oversized recipes, and bypasses zero radius. Its coupled radius is an internal feasibility parameter; general surface-normal frames and independent production width/depth controls remain pending.
- `demo-meshes/index.ts` contains the deterministic procedural generators for the built-in demo sources.
- `object-settings.ts` shares neutral defaults, bounded numeric controls, enable flags, axes, and saved-setting normalization for pre-slice object transformations.
- `mesh-deformation.ts` derives an immutable surface from the normalized source in the order X/Y/Z rotation, stretch, taper, bulge/pinch, shear, twist, bend, ripple, then organic displacement. Rotation orients the source inside fixed deformation axes. Ripple translates cross-sections sinusoidally; organic displacement uses three seeded C2 value-noise channels sampled in space, keeping coincident seam vertices together. Bulge/pinch scales perpendicular dimensions within a compact smooth band, while shear applies a volume-preserving affine lean about the stage’s axis midpoint. It runs inside each `computeContourInstance`, after morph values have been resolved and before projection, field construction, slicing, visibility, and surface features. Line-art sources bypass it. Neutral settings return the original mesh object exactly. Nonlinear transforms use conforming shared-edge refinement of the authored triangles; affine transforms preserve connectivity and rotate existing normals first, then apply inverse-transpose stretch/shear. Nonlinear normals are rebuilt while retaining the authored-face policy. Refined source geometry is weakly cached, and a per-source LRU retains at most three deformed variants within a 64 MiB geometry budget. Each variant has a distinct immutable mesh identity, so topology, geodesic, curvature, weave, and contour caches never reuse stale geometry. Deformed meshes lose the terrain height-field capability.
- `projection.ts` owns deterministic camera bases, perspective blending, the discriminated projection-warp stage, optical lens warps, mesh projection, arbitrary world-point projection, and bounded adaptive projection of nonlinear polyline spans. Besides Klein↔Poincaré and Möbius transforms, it provides a radial exponential-map sphere lift, horizon-normalized stereographic/gnomonic/Lambert azimuthal projections, and circle inversion. Projection results distinguish valid, domain-clamped, and invalid samples; singular or out-of-domain samples split runs rather than leaking non-finite coordinates. Mesh contours, spirals, silhouettes, slice-exploded output, and imported SVG centrelines use this same pure projection path.
- `svg-slice-field.ts` intersects bounded surfaces extended from SVG subpath segments with source mesh triangles. In a configurable model-space frame, segment endpoints expand linearly with depth for Divergence. Triangle bounds reject unrelated segment/triangle pairs before the intersection budget is applied. Plane intersections are clipped to each segment’s expanding bounds, welded per subpath, then passed through the contour engine’s common chaining, projection, visibility, styling, and SVG/G-code pipeline. A four-entry per-mesh cache retains these camera-independent intersections. `svg-mesh.ts` parses authored open and closed SVG subpaths independently of source uploads; detached numeric paths travel in render snapshots and local parameter history. SVG mode bypasses scalar-level slicing, LFO, spiral, and explosion.
- `scalar-fields.ts` defines the vertex-authoritative mesh scalar-field contract and constructs planar, analytic wavefront, geodesic-distance, and normalized curvature fields. Geodesic modes include one source, nearest of two sources, signed distance difference, and a two-source Voronoi payload. Curvature display fields apply a symmetric robust percentile clamp and signed contrast curve without altering the mesh. It assigns field-specific topology cache keys and resolves compatibility for LFO, divergence, continuous spiral, and slice explosion. Analytic wavefront fields provide off-vertex evaluation and gradients; intrinsic fields interpolate finite vertex values without inventing an ambient evaluator or gradient and omit invalid samples.
- `mesh-topology.ts` builds and caches deterministic mesh connectivity. It stores lexicographically ordered unique edges, Euclidean edge weights, compact bidirectional adjacency, edge face incidence, boundaries, non-manifold edges, connected-component labels and sizes, and isolated vertices in typed arrays. A `WeakMap` keys the immutable derived topology by the installed mesh object; invalid triangles and non-finite or zero-length edges are diagnosed and omitted from adjacency.
- `mesh-geodesics.ts` computes deterministic single- and multi-source shortest paths over the cached weighted edge graph. Multi-source solves also return nearest-seed vertex labels; equal-distance ties select the lower seed vertex independent of source order. Unreachable vertices retain `Infinity` and label `−1`. Directional seeds use the normalized model-space extreme with vertex index as the tie-break. These values are **surface graph distances**, not continuous exact geodesics.
- `mesh-curvature.ts` computes cached Gaussian curvature from area-normalized angle defect and signed mean curvature from the cotangent Laplacian and oriented vertex normals. Scalar-only smoothing is deterministic and cached by method/iteration count. Boundary, isolated, degenerate, and non-manifold vertices are masked rather than converted into extreme values.
- `hyperbolic-tiling.ts` generates deterministic regular `{p,q}` tilings in the Poincaré disk. It constructs the central polygon from its hyperbolic circumradius, reflects polygons across diameter or orthogonal-circle geodesics, deduplicates tiles and unoriented edges with stable quantized keys, enforces a fixed edge cap, and samples arcs into transferable line-art runs.
- `contour-engine.ts` is the pure rendering coordinator. It calculates scalar fields, delegates projection math to `projection.ts`, optionally warps slice fields with in-plane LFOs, adaptively subdivides nonlinear intersections, slices triangles, and explicitly extracts two-source Voronoi boundaries where nearest-source labels differ. It then chains line segments, performs visibility and silhouette work, and returns SVG plus grouped centreline toolpaths. Exact results also carry a compact optional `sequenceSource` measured while slice identity still exists; quick previews deliberately omit it. Final contour runs carry optional normalized visual line-weight metadata so expressive G-code can map the same appearance bands to Z pressure without reconstructing contour indexes. Output effects compose in a fixed order: geometry effects and clipping, path colour/weight styling, halftone styling, chromatic copies, map annotations, then document overlays. Mesh contours, imported SVG centrelines, and generated hyperbolic tilings share those composition rules. It must not read the DOM.
- `slice-rays-settings.ts` shares ray controls, defaults, compatibility checks, and saved-setting normalization. `slice-rays.ts` retains closed planar parity and boundary clipping, using each divergent slice's actual plane. `slice-ray-surface.ts` collects interpolated surface normals while source-triangle ownership is available and samples outward rays on curved or intrinsic contour runs, including open runs. Analytic fields use outward distance-field gradients to propagate rays from the spherical origin or cylindrical axis and reject entry/tangent crossings by the signed dot product with the source-surface normal; modulated planes use numerical gradients of the cutting evaluator; intrinsic fields use surface normals perpendicular to the contour without inventing an ambient scalar field. Closed-mesh normal orientation is corrected using signed volume, with cached topology excluding open/non-manifold surfaces from that correction. Normal arrays and ray-gradient metadata remain in the per-mesh contour cache, independent of ray enablement. Ray origins interpolate the same explosion offsets as the contour, translating every fade dash together. The coordinator projects rays after measuring source contours and uses background-aware depth visibility before the common style/clipping/export pipeline. Straight non-planar rays do not trace the cutting surface or perform mesh collision tests. Faded toolpaths preserve gaps during G-code travel optimization, including through morph grouping. Spiral, weave, SVG cutting paths, and line-art sources bypass this stage.
- `contour-refinement.ts` reconstructs sparsely sampled planar contour bends from interpolated surface normals before chaining, projection, visibility, and corner detection. It only refines spans whose tangent departs from the chord by more than ten degrees, uses a quality-dependent model-space tolerance, and caps subdivision at 64 segments per source span. Shared intersection indexes preserve closed topology; the existing slice cache retains refined points. Authored surfaces, quality 1, intrinsic fields, and nonlinear slicing fields bypass this stage. SVG and plotter paths consume the same refined geometry.
- `contour-features.ts` measures deterministic projected slice descriptors after projection and hidden-line filtering but before decorative path effects. Ordinary contours retain their scalar-field slice indexes, continuous spirals use phase bins, imported line art uses source runs as pseudo-slices, and Morph results average corresponding descriptors.
- `euclidean-rhythm.ts` owns deterministic Bjorklund rhythm generation, rotation, contour-energy resampling, and stable automatic hit alignment. `sequencer-project.ts` defines the version-two project, timing/probability/expression discriminated unions, expressive lane presets, and separate melodic/drum lane settings; these modules are DOM-free foundations for the sequencer runtime and workspace.
- `music-quantization.ts` robustly normalizes descriptor values, rank-maps them across a selected scale/register, and applies deterministic octave voice leading plus a bounded maximum leap. `contour-sequence.ts` resamples an ordered descriptor stack onto each lane's grid and produces the shared melodic/drum step representation, including Euclidean candidate gates and bounded expression values.
- `sequencer-playback.ts` resolves Grid and Fit lane events against a 960-PPQ global transport. Fit positions remain reduced rational ticks, Grid swing offsets only odd paired steps, phase changes step identity without rotating the Euclidean mask, and optional bar horizons restart lane phase. It also owns next-bar commits and bounded master-cycle calculations. `sequencer-probability.ts` applies stateless coordinate-hashed Fixed or Contour probability after the Euclidean gate; Repeat omits cycle identity while Evolve advances only at held-cycle boundaries.
- `sequencer-events.ts` is the shared live/export event compiler. It applies mute/solo state, exact lane timing, step lookup, seeded trigger probability, and independently seeded expression in a stable order. Shared helpers resolve accent velocity, octave transposition, articulation, and ratchet counts so Web Audio and MIDI consume identical decisions. `web-audio-engine.ts` is the browser-only adapter: audio context creation is deferred to `start()`, a 25 ms timer fills a 100 ms look-ahead window, delayed polls skip stale events, and pause/seek/stop cancel tracked sources. Its sample-free melodic voices expose oscillator, filter, sub-oscillator, and ADSR settings; its 808/909-inspired percussion synthesis covers kick, snare, hats, clap, rimshot, toms, congas, cowbell, crash, and ride. Explicit choke groups stop their preceding voice.
- `animation-playback.ts` owns DOM-free playback timing: monotonic playhead resolution, loop wrapping, FPS preview deadlines, dropped-frame behavior, and frame stepping. `slicer.ts` supplies the browser clock, schedules animation frames, and requests quick or exact contour renders.
- `animation-frame-cache.ts` owns bounded playback-frame storage and idle-worker scheduling. Stable FPS slots support replay and bounded look-ahead; memory pressure progressively halves temporal sampling density while preserving timeline coverage. Project/mesh generations invalidate stale entries. `slicer.ts` owns SVG presentation, caches only quick playback results, and retains exact pause/export rendering. See `docs/ANIMATION.md` for budgets and lifecycle rules.
- `polyline-styling.ts` owns deterministic post-processing of finished 2D runs: sharp-corner detection, Ramer–Douglas–Peucker simplification, coordinate-seeded Humanizer displacement, and Yarn cut-and-curl selection and geometry. Keeping these transformations outside the contour coordinator makes them independently testable and reusable by future source types.
- `block-glitch.ts` owns deterministic rectangular glitch-region placement and plotter-real cut-and-translate geometry. Every block samples immutable finished linework; source windows and optional destination windows are removed from the base before translated fragments continue through Kaleidoscope, mask/artboard clipping, and Vector zoom.
- `scan-band-glitch.ts` resolves regularly spaced horizontal or vertical glitch bands with monotonic seeded selection. It reuses the block-glitch cut-and-translate kernel so density changes reveal stable additional bands and SVG/G-code receive identical sync-tear geometry.
- `staggered-slices.ts` partitions a centered region into contiguous strips and assigns ramped, alternating, or seeded displacement. Its resolved rectangles reuse the common block-glitch geometry kernel and remain identical across SVG and G-code.
- `wraparound-tear.ts` shifts one full-width or full-height band along its long axis, splits displaced fragments at the drawable edge, and wraps overflow to the opposite edge without losing plotter marks. It shares the rectangle clipping primitives used by the other glitch effects and runs identically for SVG and G-code.
- `tile-shuffle.ts` partitions a centered region into an equal-cell grid, deterministically selects a bounded subset, and resolves a seeded one-cycle permutation with no fixed cells. Its immutable-source rectangle mappings preserve SVG/G-code parity and ensure every selected destination receives exactly one selected source tile.
- `sample-and-hold.ts` resamples finished runs at bounded arc-length intervals and holds X or Y across fixed-size sample groups. It preserves closed-run closure, supports a continuous geometry mix, caps emitted samples, and feeds identical stepped centrelines to SVG and G-code.
- `contour-weave-settings.ts` shares bounded model-space fabric controls across the UI, runtime, worker snapshots, migrations, and randomization. `contour-weave.ts` constructs warp/weft iso-lines and ribbon sides directly on source triangles from two material-coordinate fields. Crossing indexes and gaps are determined on that surface before camera projection, so projected overlaps between separate folds never become false weave crossings. The coordinator chains each thread's indexed 3D segments, projects them, and applies the shared depth-buffer visibility test before ordinary downstream geometry effects. The weave replaces regular scalar-field slicing while enabled and is unavailable for line-art sources. A four-entry per-mesh cache is independent of camera state; previews retain the material grid. Equal ink colours share a pen group, and `preserveGaps` prevents G-code travel optimization from reconnecting material cutouts.
- `misregistration.ts` creates one to three deterministic colour-copy transforms around the artboard centre. The contour coordinator re-clips these explicit runs to the artboard and active mask, serializes them as SVG layers, and emits each colour as a separate plotter pen group.
- `generative-mask.ts` evaluates the deterministic superellipse and dual angular-LFO output mask, creates its SVG boundary, and clips polylines for SVG/G-code parity. Fractional oscillator counts crossfade adjacent integer harmonics so morphing never opens the closed boundary.
- `kaleidoscope.ts` clips finished polylines to a radial wedge and alternately mirrors them around the artboard centre, preserving identical geometry for SVG and G-code.
- `vector-zoom.ts` crops rectangular or circular source regions, clears destination windows, uniformly scales vector detail into corner insets, and constructs segmented dashed borders and leaders for identical SVG/G-code output.
- `slicer-worker.ts` is deliberately small: it stores the current transferable mesh or line-art source, invokes `computeContours`, and reports results or errors. Line art transfers packed 3D points and run offsets plus a source-kind discriminator.
- `generative-terrain.ts` generates deterministic open square height fields using domain-warped gradient noise, ridged octaves, downhill drainage incision, and conservative talus relaxation. A regular grid has upward winding and no walls, floor, or edge falloff. Its finite bounded source controls share defaults and ranges with React. The generation queue transfers buffers and ignores stale results across source changes.
- `mapAnnotations.ts` places collision-tested contour-aligned labels using scalar positions retained through finished path effects, and subtracts the union of rotated rectangles in one segment pass for physical text and feature clearances. Cached rectangle bounds reject unrelated segments before clipping, avoiding repeated fragmentation across dense map layers. SVG and plotter output share vector lettering; implicit metre values are illustrative. No elevations are inferred from path length. Explicit index line weights take priority over the topographic fallback.
- `generativeMesh.ts` generates indexed meshes from implicit fields. Its worker transfers array buffers rather than cloning large arrays.
- `svg-mesh.ts` converts filled SVG artwork into extruded mesh geometry or pruned medial/scale-axis centreline polylines. Extrusions carry `preserveSurface` through mesh normalization and worker transfer: slicing intersects the authored triangle surface without normal-based smoothing, and contour SVG serialization follows the sampled polylines without spline overshoot. This preserves planar faces and sharp corners, including the flat portions of explicitly beveled extrusions. SVG Y-axis reflection also reverses triangle winding to keep faces outward-facing.
- `toolpaths.ts` owns rectangular clipping, near-endpoint joining, greedy run ordering, and reversible 2-opt refinement. Optimized results retain source-run indexes so export-only metadata such as line-weight pressure stays aligned after ordering or reversal.
- `gcode.ts` converts grouped toolpaths into machine instructions, applies an export-time clipping safety net, and supplies conservative serializer fallbacks.
- `gcode-3d-toolpaths.ts` defines the DOM-free machine-point and operation model for opt-in coordinated XYZ plotting. It converts already clipped and travel-ordered UUNA runs into constant-contact or bounded arc-length-resampled tapered, modulated, and curvature-relieved strokes, then applies fixed-angle tip-offset compensation relative to Contact Z before serialization.
- `gcode-nib-footprint.ts` samples final 2D runs for broad-nib spacing guidance. Its inter-run merge warning is deliberately approximate; the preflight overlay shows nominal nib width while physical deformation remains a calibration concern.
- `gcode-surface-presets.ts` stores validated three-point paper-plane calibrations in browser-local storage under the selected UUNA machine profile. These machine presets remain separate from artwork and render snapshots.
- `gcode-calibration.ts` creates the deterministic 120×90 mm UUNA contact ladder, angle-offset crosses, and taper fan plus a full-bed three-point surface pattern as ordinary 3D machine operations, so calibration files share the production serializer and validator.
- `gcode-profiles.ts` is the single source of truth for machine names, origins, working envelopes, motion defaults, and legacy profile resolution. UUNA TEK 3.0 profiles cover the official landscape A3, A2, A1, and A0 working areas.
- `gcode-layout.ts` resolves the physical export layout. When enabled, it rotates portrait toolpaths clockwise only when the canvas does not fit the selected machine directly but its swapped dimensions do; the serializer and preflight consume the same transformed runs.
- `gcode-validation.ts` independently parses and simulates the serialized machine program. Its strict profile checks enforce setup order, the supported command subset, feeds, pen state, sheet bounds, safe pen changes/shutdown, and expose draw/travel segments plus preflight statistics.
- `grbl-serial.ts` owns the Web Serial adapter and conservative GRBL sender. It removes export comments, preserves source-line diagnostics, sends one command at a time only after `ok`, surfaces `error:`/`ALARM:` responses, and uses GRBL feed hold for cancellation. `slicer.ts` owns permission prompts, motion confirmation, and connection/progress presentation.
- `paper-orientation.ts` normalizes standard and custom dimensions into explicit portrait or landscape orientation. `slicer.ts` uses it to keep the Canvas selector, dimensions, and paper preset synchronized.
- `slicer-export.ts` maps browser runtime state into SVG/G-code export artifacts and safe download names. It is DOM-free; `slicer.ts` remains responsible only for waiting for a current render, clipboard access, and initiating downloads.
- `render-settings.ts` is the exhaustive browser-state-to-worker-settings adapter. Its key list is compile-time checked against `ContourSettings`, omits runtime/request-only fields, derives the document title, and detaches mutable morph maps.
- `parameter-history.ts` owns the bounded, branch-aware undo/redo timeline. It clones values at its boundary and exposes navigation availability without knowing about controls or rendering.
- `parameter-migrations.ts` normalizes legacy and incomplete parameter snapshots before the browser runtime applies them. Compatibility defaults, legacy lens conversion, and saved vector-zoom validation belong here rather than in DOM restoration code.
- `animation-project.ts` owns the versioned, DOM-free animation project model and immutable timeline editing operations. `animation-interpolation.ts` applies easing and typed interpolation, including rounded integer counts, discrete seeds, and RGB colours. `animation-validation.ts` checks persisted project invariants, `animation-migrations.ts` repairs incomplete version-one data, `animation-history.ts` creates an animation-scoped `ParameterHistory`, and `animation-storage.ts` owns the versioned IndexedDB envelope and stable browser-local project association. Evaluation produces one ordinary `ContourSettings` snapshot and always disables the separate overlaid X/Y Morph feature. See `docs/ANIMATION.md` for the complete contract.
- `animation-video-export.ts` defines deterministic frame counts, endpoint-inclusive timeline times, encoder timestamps, effective opaque backgrounds, filenames, and cancellation contracts. `video-encoder.ts` is the browser adapter around Mediabunny's WebM muxer and WebCodecs canvas source; it selects VP9 with VP8 fallback, respects encoder backpressure, and owns raster/encoder cleanup.
- `components/animation/AnimationExportAction.tsx` owns the export button and native modal confirmation dialog, reusing `AnimationExportControls.tsx` for resolution/bitrate choices, dimensions, and estimated size. The timeline pauses playback when opening the dialog, publishes quality-change commands as selections change, and publishes `export` only after **Start export** confirmation. `slicer.ts` applies settings through immutable project updates, commits history/autosave, and rechecks codec support. Encoder and rasterization settings come from the captured project at export start. Cancel/Escape dismiss without encoding, and timeline keyboard shortcuts are suspended while the dialog is open.
- `colorPair.ts` creates random ink/background combinations and ink-anchored harmonic gradients in OKLCH while enforcing contrast and gamut constraints.
- `map-features.ts` creates seeded cartographic building clusters, six landmark symbols, and woodland inside the convex footprint of finished contours. It also styles already projected terrain route centrelines as road/river banks and physical clearances. It never invents road, river, or lake geometry from the drawing footprint.
- `terrain-routes.ts` reconstructs the dedicated terrain grid from normalized vertex coordinates, independently of welding order. It solves strictly downhill flow on triangle edges, accumulates drainage, and selects connected stream runs that end at boundaries, real depressions, or earlier streams. Roads use grade-limited, distance/grade-weighted Dijkstra paths within traversable regions. Corner relaxation is accepted only when surface sampling retains descent or the road grade limit. Bounded per-mesh caches keep camera edits from rerunning route solves. `slicer.ts` marks the dedicated source with `terrain` only in Z-up orientation; `slicer-worker.ts` retains the flag. The contour engine projects, hides, and post-processes these model-space routes with the terrain before passing them to map annotations. Other sources never receive a decorative fallback.
- `map-settings.ts` shares bounded map-effect defaults and control descriptors between the renderer, React controls, runtime bindings, snapshots, migrations, and randomization.

### Internal 3D workspace

`three-d-project.ts` owns the shared workspace mode type, source/project/job contracts, session source association and deterministic physical placement. `mesh.ts` now retains raw bounds, center and normalization radius alongside its unchanged normalized buffers. Runtime source metadata records up-axis correction and whether raw mesh units are available. Physical placement uses the shared shaped mesh, uniform millimeter scaling, X/Y/Z print rotation, centering and bed offsets. Neither camera nor drawing artboard coordinates enter this transform.

`three-d-worker.ts` applies `deformMesh` and physical placement away from the main thread. `three-d-runtime.ts` owns one lazily created worker, coalesces pending edits, transfers detached copies, rejects old request/source revisions and terminates on mode exit/page hide. Ordinary previews publish the untreated surface and bounded exact planar overlays; errors in slicing retain the source for inspection. Explicit preparation uses request/source revision guards and stage progress. Duplicate blur/resize requests do not invalidate an unchanged artifact. Cancel, mode exit or a new edit during preparation terminates the worker so synchronous native work cannot later publish a stale solid.

`slicer.ts` owns mode transitions, the current source and physical project, a mode-scoped history containing shared settings and physical edits, and a bounded session map of physical settings by source content. Config controls remain mounted; shared Object edits are committed as one Config history transaction on exit. `threedprojectchange`, `threedstatechange` and `threedstaterequest` bridge React controls and runtime. The existing mode compatibility event now accepts `3d`; transitions stop Sequencer and restore Animation's frozen Config settings before binding the source. Export/copy handlers reject 3D actions before and after awaiting drawing work.

`components/three-d/ThreeDWorkspace.tsx` owns controls and lazily mounts `three-d-scene.ts`. The small Three.js adapter owns the independent Z-up cameras, OrbitControls, scene and GPU resources. Rendering is event-driven; source replacement/mode exit disposes geometry, materials, controls, observers, renderer and context. The reference bed is display-only; the oriented millimeter vertex buffer is authoritative. Inspection camera state is intentionally absent from geometry jobs and history. The camera exposes only its direction for an explicit alignment command. Overlays and solids use the same print rotation and bed translation; no camera value enters automatic jobs.

`slice-fan.ts` shares the virtual source, tangent and fan-plane calculation between drawing and 3D, keeping Divergence consistent across modes. `slice-spacing.ts` contains the unchanged gap-easing function shared by drawing and 3D. `three-d-slices.ts` resolves supported planar fields and ordered eased levels, including per-slice normals for Divergence, calls the strict `slice-geometry.ts` extractor, selects levels through `slice-treatment.ts`, and converts source contours to placed viewport segments. View depth is frozen in the source project; `threedalignview` explicitly removes print rotation from the inspected direction and updates the shared field plus project history. The original shared controls remain single instances in the rail.

`three-d-preparation.ts` separates shaped/uniformly scaled source construction from print orientation and bed placement. `three-d-cache.ts` retains at most one physical base and one exact planar slice set per worker, with a combined 64 MiB typed-buffer retention cap (including exact source-coordinate/index copies). Base keys include source revision, normalization, resolved Object settings and physical size; exact source arrays are compared as well. Slice keys include the actual planar field and source revision. Selection, treatment and placement edits reuse those inputs; source/size/Object edits replace them, and slice-field edits replace only the slices. Oversized entries are computed without retention. Reply buffers are separate from cached buffers, so transfer cannot detach them. No audit or Boolean result is cached; every preparation still validates its source and exact placed result. Worker termination releases the cache. `three-d-worker.ts` initializes Manifold from a local emitted WASM asset only after `threedprepare`. The preparation coordinator checks the source, creates bounded circular capsule recipes/tools, performs Inset/Emboss, then reruns geometry auditing on the exact Float32 placed result through `print-manufacturing.ts`. It returns separate geometry checks, issue counts, optional approximation measurements and manufacturing advisories. Rejections retain only the untreated source. React and scene code receive no native handles. `threedcancel` terminates the native worker; settings edits also invalidate accepted artifacts and cancel obsolete preparation. Camera/source comparison and overlay visibility are display-only. `ThreeDSlices.fieldKey` identifies the source revision, selected field mode, actual planar field/levels and selection, excluding camera and placement. The viewport resets hidden overlays when that completed key changes (including undo), so inspecting one treatment cannot leave new field contours hidden. Source comparison uses a weak reference to the current prepared artifact and cannot carry into a new result or retain obsolete buffers. Scene initialization reapplies the current visibility state after the lazy adapter becomes ready. The prototype does not serialize solids or persist 3D projects across reloads, and its coupled circular profile is not the planned independent surface-normal width/depth implementation.

`generated-solid-cleanup.ts` operates only on generated tool, Boolean and placed buffers. Tool and placed buffers use exact-coordinate cleanup; Boolean-result buffers use `ThreeDProject.resultWeldToleranceMm` (0.00001 mm for new projects, zero for exact-only). A spatial hash searches neighboring buckets and chooses the earliest fixed representative within the Euclidean tolerance. Representatives never move, and already merged vertices never become representatives, so chaining cannot exceed the per-vertex displacement bound. Strictly zero-area faces and unused vertices are removed after welding, preserving winding. Every result is audited afterward; source imports and neutral operations remain unchanged. Cleanup counts, stage tolerance and maximum measured displacement travel through `ThreeDPreparation.cleanup` on both acceptance and rejection and are disclosed in the panel. The setting participates in 3D history and request invalidation; source and contour caches remain reusable. No hole filling or general surface simplification is performed.

`exact-adjacent-overlap.ts` resolves adjacent-triangle candidates rejected by the floating-point direction-cone filter. It decodes finite IEEE coordinates onto an exact dyadic integer grid and evaluates plane/cone signs with BigInt. This distinguishes thin valid neighbors and near-coplanar folds from actual overlap beyond a shared edge/vertex. Nonadjacent contact tests retain their conservative proximity tolerance. The change does not claim that the entire intersection audit uses exact predicates. Generated-mesh cleanup and this predicate resolve the eight-slice rounded-cube and analytic-torus regressions; larger invalid results remain rejected.

Construction allows 32,000 path vertices and 8,000,000 estimated capsule triangles, with 64 loops. The kernel, topology, intersection, shell and optional thickness stages agree on a 500,000-triangle mesh ceiling; intersection traversal allows 20,000,000 work units. The 64 MiB kernel buffer cap, 64 MiB geometry-cache cap and 250,000-triangle source slice-extraction cap remain separate. These are bounded working allowances, not guaranteed fast or print-ready workloads.

### Browser orchestration

`slicer.ts` is the integration boundary for browser-only behavior. It owns the current settings, binds form controls, schedules worker renders, connects the pure history timeline to DOM restoration, manages randomization, handles orbit/pan gestures, and coordinates preview, export, and direct serial plotting. Keep computation that can run without `document`, `window`, or mutable UI state out of this module.

## State and events

Most ordinary settings live in the runtime `state` object. Before rendering, `settingsSnapshot()` creates a serializable object for the worker. Meshes are sent only when their version changes; render requests then reference the worker's current mesh.

Complex React controls communicate through custom DOM events:

- `morphchange` and `morphseconddimension` synchronize morph targets.
- `randomlockchange` and `randomlockbulk` coordinate parameter locks.
- `randomizegroup` sends the randomizable parameter IDs from one accordion to the runtime.
- `gradientchange` publishes normalized gradient stops.
- `lineindexcolorschange` publishes one-based contour-index colour overrides.
- `setgradient` synchronizes generated gradient stops into the React editor.
- `restoreparameters` restores React-owned control state during undo/redo.
- `captureparametersnapshot` and `applyparametersnapshot` bridge the React snapshot manager to the runtime-owned parameter and lock state.

Named parameter snapshots are stored locally in IndexedDB by `parameter-snapshots.ts`. They use the same render-setting shape as undo/redo and additionally preserve randomization locks; active X/Y morph targets are already part of the render settings.

These event names and their payloads are internal interfaces. Change producers and consumers together.

The top-level Config/Animation/Sequencer/3D switch retains the `animationmodechange` compatibility event. Animation uses `animationcommand`, `animationstatechange`, `animationstaterequest`, and `animationexportprogress` for transport, timeline state, initial synchronization, and sequential export status. In Animation mode, `slicer.ts` freezes a normal render-settings snapshot and intercepts morphable control input before the ordinary Config bindings can mutate runtime state. Quick playback renders use explicit evaluated snapshots and do not enter parameter history; leaving the mode restores the frozen Config snapshot.

Sequencer uses `sequencercommand`, `sequencerstatechange`, and `sequencerstaterequest`. React owns its accessible transport and lane-grid presentation; `slicer.ts` owns the in-memory project, exact contour source, phrase generation, transport, and Web Audio lifecycle. `contour-sequence.ts` converts only the latest exact `ContourSequenceSource` into visible lane steps. While stopped, project or source changes replace the phrase immediately. While playing, `WebAudioEngine.setPhrase()` queues them after already-scheduled audio at a global bar boundary; its swap callback clears the Pending shape state. A requestAnimationFrame loop reads the audio engine's monotonic tick only for the visual playhead, while the 25 ms/100 ms Web Audio look-ahead continues independently.

The versioned musical project autosaves as a small JSON envelope in browser-local storage through `sequencer-storage.ts`; it excludes mesh bytes and derived contour sources. Restore migrates version-one lanes to explicit neutral-expression version-two lanes, then validates the complete melodic/drum discriminated union before the runtime accepts it. `midi-sequence-export.ts` writes a bounded format-1 Standard MIDI File using the transport PPQ. It calls the same `compileProjectEvents()` path as Web Audio, expands deterministic ratchets, rounds absolute rational event positions rather than accumulating step errors, assigns percussion to General MIDI channel 10, and requires an explicit finite bar count.

Timeline edits use a dedicated `ParameterHistory<AnimationProject>`, with slider and pointer changes coalesced at gesture boundaries. Keyframe dragging, duplication, easing, loop state, timing, keyboard commands, and camera gestures all update the animation project without writing into Config state. React owns the accessible timeline presentation and publishes commands; `slicer.ts` remains authoritative for selection, locking, project history, and rendering.

The current animation project autosaves to the separate `slicewise-animations` IndexedDB database after coalesced history commits. A UUID retained in local storage identifies the browser-local workspace independently of source filenames. On first entry to Animation mode, persisted data passes through migration and is restored only when its frozen base settings match the current Config snapshot. Animation persistence never stores source mesh or artwork bytes and remains separate from named parameter snapshots.

Video export evaluates an endpoint-inclusive deterministic frame schedule and requests one exact hidden worker render at a time. Each returned SVG is flattened onto a fixed even-sized canvas before the encoder accepts it with an explicit timestamp. The Mediabunny adapter writes a silent WebM in memory while enforcing WebCodecs backpressure; cancellation closes the source and output, and export frames never replace the visible preview or Config export state.

## Rendering and concurrency

Contour requests are assigned monotonically increasing IDs and mesh versions. Results from replaced meshes and stale full-quality responses are ignored. During an active orbit or roll gesture, a completed same-mesh quick response may be shown transiently while a newer request remains queued; outside direct manipulation, stale quick responses are discarded. The runtime adjusts throttling using triangle count, preview contour count, visibility work, curve quality, and preview morph instance count.

Interactive preview state is intentionally distinct from exact export state. Quick responses omit export toolpaths and sequence descriptors, and adapt contour density, curve precision, and morph-grid dimensions. Detail begins at two-thirds, rises through discrete steps to full detail after several fast end-to-painted-frame measurements, and falls with a wider slow-frame threshold to avoid oscillation. A completed gesture always requests an exact render with the full contour and morph settings, and only the latest full-quality response updates the stored SVG, toolpaths, and sequencer source. Retaining the previous exact sequence source while a quick or replacement render is pending prevents provisional geometry from changing a playing phrase. The measured preview cost also replaces the conservative static throttle estimate once samples are available. Export actions automatically request a current full-quality result when necessary.

Pan and wheel zoom use a temporary SVG group transform for immediate feedback. Their exact clipped geometry is recomputed when the pointer gesture ends or wheel input has been idle for 140 ms. Orbit and roll still require worker projection and visibility work, so they use the lightweight quick-render path while dragging.

Object deformation runs in the contour worker, so source buffers are installed only when the source changes. Every numeric object parameter travels in the ordinary render snapshot and is evaluated independently for each morph instance or animation frame. Camera edits reuse the same deformed mesh. Refinement normally targets edges at most 1/16 in source bounding-box-normalized coordinates. Active bulges below 50% width select 1/32 refinement, or 1/64 below 25%, independently of centre and amount. Ripple wavelength or organic feature size below 50% also requests 1/32 refinement; the finest active requirement wins, independently of phase and seed. Source refinement caches retain up to three density variants. Work is bounded with eight passes and a maximum of 250,000 triangles (or the original count for larger sources); exceeding required refinement budgets reports a structured render error. Cached refinement copies are limited to 32 MiB per source. Quick and exact renders share this surface. Object reset uses the ordinary parameter history and removes both dimensions’ object morph targets.

Scalar fields with a non-empty `cacheKey` use a bounded set of at most eight 3D slice topologies per mesh. Every active planar decorator and contour-spacing parameter that changes topology participates in that key. The model-space `up`, `x`, `y`, custom, analytic wavefront, and geodesic fields opt into this cache. Orbiting can then reproject cached polylines instead of rescanning every triangle at every contour level. Camera-axis fields use an empty key and remain uncached because their vertex values change with the camera.

Mesh connectivity uses a separate lifetime cache in `mesh-topology.ts`. One installed mesh object maps to one immutable derived topology, reused by every surface-graph distance solve and intrinsic field. Replacing the installed mesh naturally releases the old entry through the weak key. `scalar-fields.ts` additionally retains at most eight least-recently-used single-seed distance buffers and eight two-seed nearest/label buffers per mesh, preventing directional morphing from growing memory without bound. `mesh-curvature.ts` weakly caches both raw methods and their bounded 0–20 smoothing variants for the installed mesh.

Session 13 profiling retained this worker-local cache design. On the 312-vertex/576-triangle release fixture at 24 contours and quality 7, cold exact renders ranged from about 9–46 ms and warm renders from about 5–12 ms on the audit machine; topology transfer at mesh installation would add protocol complexity without addressing the measured bottleneck. The maximum UI tiling sweep found `{11,12}` at depth 6 reached the 12,000-edge cap with 29,436 sampled nodes in about 18 ms. Its installed point/normal/offset typed arrays occupy about 0.72 MiB per main-thread or worker copy; source replacement releases those arrays and mesh-keyed weak caches.

Nonlinear projected runs are adaptively subdivided in world space before visibility splitting and SVG/G-code simplification. The sheet-space chord tolerance follows curve quality, with a maximum recursion depth of eight and at most 8192 projected nodes per source run. Exact SVG and G-code therefore share the same curved centreline geometry; quick previews naturally use their reduced curve quality. Paired source/output samples keep visibility coordinates aligned when slice explosion displaces the emitted geometry.

The hidden-line depth buffer rasterizes projected source triangles directly for affine and bounded disk transforms. Spherical and inversion modes adaptively tessellate source faces to a depth-buffer-pixel error tolerance, with a recursion cap of four. Faces crossing a horizon or singular domain are subdivided; only finite valid subfaces are rasterized. Visibility retains its neighboring-pixel tolerance around the resulting surface.

Every render request carries an explicit detached settings snapshot, quick/exact quality, record/ignore history policy, and Config/animation-preview/animation-export purpose. Animation snapshots defensively disable both Morph dimensions and never replace the exact Config SVG/toolpaths used by ordinary export. Stale-response checks include both the request ID and purpose; animation-export results are routed away from the visible preview for the dedicated exporter.

The runtime publishes the latest timing samples through the browser Performance API as `slicewise:render:queue`, `slicewise:render:worker-roundtrip`, `slicewise:render:dom-apply`, and `slicewise:render:end-to-paint`. The visible Render statistic remains the contour engine's worker computation time.

There are two worker entry points:

- `slicer-worker.ts` for contour computation.
- `generative-mesh-worker.ts` for implicit-surface generation.

Both return structured errors instead of throwing across the worker boundary.

## Adding functionality

### Add a control

1. Put the markup in the appropriate panel using an existing shared control when possible.
2. Give it a stable, unique ID.
3. Add the setting and binding in `slicer.ts`.
4. Include render-relevant values in `settingsSnapshot()`.
5. Document the control in [`PARAMETERS.md`](./PARAMETERS.md).

### Add an import format or demo mesh

Implement import parsing in `mesh.ts` or procedural demo geometry in `demo-meshes/`, returning `{ verts, tris }`. Register uploads or demos in `slicer.ts`; normalization and normal calculation happen when the mesh is installed.

### Add a contour algorithm or output effect

Implement deterministic, DOM-free work in `contour-engine.ts` or a focused helper such as `toolpaths.ts`. Pass configuration in the settings snapshot and return any export metadata with the render result. Browser-specific toggles and enable/disable behavior remain in `slicer.ts`.

Finished-polyline transformations belong in `polyline-styling.ts` when they do not need mesh, scalar-field, projection, or document context. Effects that change the common clipping/composition order should stay coordinated by `contour-engine.ts` and call a focused helper.

### Add an export format

Keep serialization in a focused library module like `gcode.ts`. Let `slicer.ts` choose the serializer and handle browser download or clipboard APIs.

Machine/profile mapping and file metadata belong in `slicer-export.ts`; controller-neutral instruction generation belongs in `gcode.ts`.

Both mesh and line-art composition collect finished, clipped contour runs before annotation gaps, sort intact loops by descending projected area, and place opaque fills underneath the normal strokes. Open fragments are never implicitly closed. The standard colour-group pipeline supplies matching contour colours to G-code; the fill polygons are SVG-only. The optional `weatherBands` worker setting defaults to false when migrating older snapshots.
